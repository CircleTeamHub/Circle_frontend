# Web 首屏拆包与登录后预取

生产 Web 使用 Expo Router 的异步路由；开发服务器和 Android/iOS 保持同步路由。笔记 DOM 编辑器在 Web 有独立异步入口，原生端保留原来的按需同步加载和 Expo DOM bridge。Web 编辑器下载期间显示局部加载状态，DOM 就绪监控在代码加载完成、编辑器挂载后才开始计时，避免把正常下载误报为 DOM 故障。下载失败交给路由错误页；用户点击重试时，Expo 55 的 `AsyncRequireError` 会刷新当前 URL，清除框架缓存的失败 `React.lazy`。普通渲染错误仍使用原来的重试。

`npm run export:web` 将当前构建的异步 JS 路径写入 HTML 内的 `windnote-web-prefetch-assets` JSON 元素；不依赖可被后续部署替换的共享 manifest URL。列表排除 HTML 已加载的入口脚本，并优先排列笔记编辑器。列表只包含静态代码路径，没有账号、token 或业务数据。

`WebRoutePrefetch` 在实际 tab 首页挂载后等待有效登录、启动校验结束和页面聚焦，再延迟 1.5 秒开始预取。它逐个加入 `rel=preload as=script fetchpriority=low` 的 link，完成后间隔 250ms 再取下一个；这些 link 下载代码，不执行模块，也不挂载目标页面。成功的 link 保留在当前文档中供 Expo 的经典 script 加载器复用，已存在的 link 和资源记录会去重。单个可选预取最多等待 30 秒，失败不阻止用户正常导航。

退出登录、切离页面、隐藏标签页或卸载组件会停止后续调度并移除未完成的 link。浏览器可能继续已发出的传输；重新聚焦时会跳过已完成资源。支持 Save Data 的浏览器开启该设置时不预取。开发环境没有导出 metadata，因此不执行预取。

## 部署与缓存

- HTML 应使用 `Cache-Control: no-cache`，让新访问能取得当前构建的入口与资源清单。
- 带内容 hash 的 JS/CSS 等静态资源适合 `Cache-Control: public, max-age=31536000, immutable`；仅对真实存在且成功返回的文件使用，不长期缓存 404。
- 新资源应先全部上传，再切换 HTML。切换版本时保留旧 hash 文件，避免用户已打开的旧页面在后续导航时缺少代码；保留时间应覆盖站点承诺支持的旧页面会话周期。
- 预取与后续加载必须使用相同 URL 和请求模式。当前实现与 Expo 55 的同源经典 script 加载匹配，不引入 service worker。跨文档刷新后的缓存复用仍取决于服务器响应头和浏览器缓存策略。
- 配置服务器实际的 gzip/Brotli 后再比较网络传输量；本地压缩测算不代表线上已经启用压缩。

## 验证

固定合成 API 配置导出的初始三份 JS，改动前合计 14,553,867 字节 / gzip 3,140,746 字节；拆包后测算约 10.12MB / gzip 2.33MB，入口 JS gzip 减少约 26%。此数据不包含登录路由的后续小块、CSS、字体或图片，也不是失败设备的真实加载时间。SDK 55 会把多条异步路由共享的依赖汇入初始 common chunk，因此此次改动并未让首屏只包含登录业务。

浏览器 smoke 使用合成认证响应，验证冷登录不预取、登录后只预取编辑器代码且不请求笔记内容、生产 Metro loader 复用预取资源、首次路由下载失败可由用户重试恢复，以及 CSS/登录路由代码挂起时启动探针仍报告超时。Chrome 自动回归不能替代真实 iPhone Safari 与原故障网络的复测。
