# Circle 本地运营管理台

本次参考 Squady Infra `master` 的 backoffice，按 Circle 现有 NestJS、Prisma、Ant Design 和权限体系实现。所有改动与迁移只在本地完成，未部署、未创建 PR。

## 页面与权限

| 入口 | 能力 | 当前权限 |
| --- | --- | --- |
| `/push-operations` | 渠道配置状态、全局暂停、用户/设备过滤、逐设备回执、失败设备重试、定向公告 | SUPPORT_MANAGE；发送与开关还需 CONTENT_MANAGE |
| `/tasks` | 现有 8 类队列的积压、死信、最早任务和分页明细 | DASHBOARD；推送重试还需 SUPPORT_MANAGE |
| `/users/:id` | 业务时间线、最近登录会话、受信任设备、版本登记、设备更新预览跳转 | USER_READ；版本预览还需 CONTENT_MANAGE |
| `/insights` | 每日活跃、功能使用、严格顺序漏斗、注册后自然日留存 | DASHBOARD |
| `/releases` | 官方工件登记、灰度计划、强制更新阈值、版本撤回、分布与决策预览 | CONTENT_MANAGE |
| `/diagnostics` | 诊断 ID 查询、管理员失败请求摘要、业务事件、外部日志入口 | AUDIT_READ |
| `/automation-keys` | 只读自动化密钥创建、过期、最近使用与撤销 | ACCESS_MANAGE |

沿用角色权限分配，不会因新增页面自动提升已有管理员角色。所有新管理接口都有后端权限校验；页面隐藏不代替授权。

## 推送与任务

- 推送开关暂停后不再领取新任务，已有在途请求可能完成。恢复后继续处理原队列，暂停不会删除任务。
- SENT / CONFIRMED 表示渠道接受/回执确认，不代表用户已阅读。Expo 配置状态也不等于上游此刻可达。
- 推送详情仅返回登记 ID、平台、渠道及回执状态，不返回推送 token、聊天正文、完整供应商错误。
- 只有 FAILED 推送开放重试。成功或终止设备不重新投递，过期的任务版本会拒绝操作。其他队列先提供只读排查，避免重新执行资金或群管理副作用。
- 定向公告选择已发布公告和最多 100 位有效用户；公告/用户唯一约束及操作幂等键共同防止响应丢失后重复创建。
- 写操作要求原因，并在事务内记录审计；重试沿用同一操作标识。修正了共享幂等锁的 PostgreSQL void 返回值与 Prisma 驱动兼容问题。

## 时间线与统计

- 业务事件与原业务记录在同一数据库事务生成，包括消息发送、笔记/动态创建、入圈、订单、举报、登录会话建立、设备撤销和推送任务终态。
- 事件只保存类型、对象 ID、来源和时间。没有聊天正文、笔记正文、密码、密钥、推送 token、账单金额或供应商错误原文。
- App 在登录和回到前台时上报粗粒度活跃及版本。上报必须匹配有效 APP 会话绑定的设备；服务端每个账号每 5 分钟最多记录一次，设备登记数量受限。
- 活跃与留存只计主动行为；被动推送、订单后台变化、刷新会话不会被误算为用户回访。账号在多设备出现仍按用户去重。
- 采集起点持久化保存。旧埋点不回填；漏斗与留存仅使用覆盖期间注册的用户。留存的目标自然日结束后才进入分母。
- 漏斗为注册 → App 活跃 → 加入圈子 → 发消息，要求按顺序在注册后 7 天内发生。较新的注册批次还在转化窗口内，数据会继续变化。
- 存储时间统一 UTC，数据库会话使用其他时区也不会改变事件时间；统计展示时区为 Asia/Shanghai。聚合最多缓存 45 秒，同时间范围的并发查询合并。事件保留 180 天，清理任务接入现有任务心跳监控。
- 用户、举报、审计以及新页面的主要筛选可在 URL 恢复。邮箱/手机号等敏感用户搜索仅留在内存，不写入分享链接。

## App 版本管理

1. 使用现有发布流程生成真实签名工件。
2. 登记版本、构建号、下载地址、SHA-256 和大小。Android 仅接受既有 GitHub 官方发布路径；iOS 仅接受 App Store 链接。
3. 新建计划，配置来源构建范围、时间窗口、稳定灰度比例及强制更新阈值。新建版本本身不会立即改变客户端决策。
4. 用决策预览检查；也可从用户详情选择最近登记的设备，直接按它的实际版本和分桶评估。
5. Android 启动和手动检查使用同一决策，安装前继续验证工件大小与 SHA-256；iOS 使用 App Store。开发客户端和独立预生产 App 不接受生产更新。
6. 必须更新时显示阻断界面；撤回版本或停用计划后，后续检查不再推荐该版本。客户端离线时不能获知新的撤回或强制更新决策。

版本分布来自最近 30 天活跃的账号设备登记，同一物理设备切换账号可能重复。它不是应用商店下载量。

## 诊断与自动化

- 错误页面保留 HTTP 状态和可复制的诊断 ID，可跳到相同 ID 的诊断记录。管理员失败请求只保存静态路由模板、方法、状态和操作者，不保存请求体或错误原文。
- 权限服务不可用与真的 403 分开提示；网络故障保留登录状态。数据库不可用时诊断落库也可能失败，此时仍需使用后端日志/Sentry 中的相同请求 ID。
- `VITE_SENTRY_URL`、`VITE_GRAFANA_URL` 等现有配置用于外部入口；本次不会创建或连接新的云服务。
- 自动化密钥只显示一次，数据库保存 SHA-256 摘要。默认表单 7 天、最长 30 天；关闭、后台或换账号后不再展示。密钥不留在查询/变更结果缓存。
- 工具入口在查询密钥前先按 IP 限流，并复用现有鉴权数据库预算。每次请求核对密钥范围、期限、撤销状态以及当前管理员权限；读取也写审计。工具密钥不能登录 App、调用一般管理接口或读取加密聊天正文。
- 支持 tasks、push、timeline、analytics、diagnostics 五个独立只读范围。精确范围独立校验，即使两个范围对应同一种后台权限，也不能互相替代。
- 后端仓库提供 `scripts/console-read.mjs`。设置 `CIRCLE_CONSOLE_URL`（本地默认 `http://127.0.0.1:3000/api/v1/`）和 `CIRCLE_CONSOLE_KEY` 后，运行 `node scripts/console-read.mjs tasks`。只允许 HTTPS 或 loopback HTTP，密钥只放 Authorization 请求头。

## 本地验证

- 后端：`npm test -- --runInBand`、`npx tsc --noEmit`、`npm run build`。
- 真实本地 HTTP/PostgreSQL：`npx ts-node -r tsconfig-paths/register scripts/test-console-local.ts`。仅允许 loopback 数据库，创建并清理独立 UUID 测试数据。
- 管理台：`npx vitest run --maxWorkers=2`、`npm run build`。
- App：`npm run typecheck`、`npm run lint`、`npm test`，以及 `npx jest --watchman=false --runInBand src/components/app/AppOperationsHost.spec.tsx src/features/app-update`。

浏览器验收覆盖了页面读取、错误诊断跳转和版本决策预览。真实升级包下载安装、App Store 发布以及新功能在真机上的完整操作不属于本次浏览器验收结果。
