# 跨重启页面缓存（2026-11-05）

## 原因与实现

上一轮主要修复的是内存中的页面复用、刷新与失效。彻底结束 App 进程后，Map、组件 state 和未持久化的 Zustand 数据都会消失；图片磁盘缓存和聊天 SQLite 仍在，但它们不能直接替代页面列表快照。

本次复用原有加密 MMKV 保存原生端页面展示快照，按账号区分。根布局已有存储初始化门；页面在 state 初始化或布局阶段同步读取快照，然后继续后台 GET。缓存是否存在决定初次转圈，缓存的新鲜度决定后台核对；已缓存的空列表也算有效快照。

## 范围

- 笔记列表/分组/详情/收藏副本状态、下架/回收站/选择笔记、群笔记管理的展示行、远端草稿摘要。
- 收藏列表的文字、实际媒体缩略图、来源和时间；实时来源 DTO 不写入展示快照，发送前继续校验。
- 好友与标签/搜索/新的朋友、备注与权限设置展示资料、用户头像/封面、群资料/成员目录、圈子列表/详情、朋友圈相册与相关内容列表。
- 已确认的隐私/自动回复设置、上次钱包页确认的余额/流水、公告和徽章。
- 临时聊天列表保留标题和状态；邀请链接不持久化，过期状态按当前时间重新计算。
- 消息列表增加同步的名称/头像等展示快照，在聊天 SQLite 异步打开期间先显示列表。新快照没有消息正文或草稿，不修改服务端全量快照标记；真实预览和聊天内容继续从现有聊天库恢复。

## 一致性与权限

- 磁盘归属使用账号 ID；运行中的异步响应仍检查会话代际、缓存清理版本及对应领域成功写入信号。
- 写入只来自成功响应。好友/群/圈子/朋友圈等修改会使相关快照更新或失效；旧 GET 不能在修改或清理之后写回旧版本。
- 群当前管理权限验证不落盘。恢复的名单只读，敏感操作等待本次权限结果；明确拒绝访问或删除会清理相应快照。
- 钱包恢复值仅供展示，不进入实时余额 store，也不参与交易校验。设置、徽章、笔记详情及收藏的相关操作继续等待实时验证。
- 用户资料持久化投影移除手机号、邮箱、微信和 QQ。原生端使用现有加密存储；浏览器不新增明文持久化。
- 不缓存密码、登录凭证、二维码凭证或阅后即焚消息正文。主动退出账号和清理缓存会删除对应页面快照；加密聊天库及用户草稿沿用各自的清理语义。

## 边界

- 新版至少成功读取一次对应页面，才会建立新快照；安装后第一次进入未看过的页面仍可能加载。
- 首次无缓存、主动清理、权限变化、数据写入导致相关缓存失效，以及容量淘汰时，可能需要重新建立快照。
- 页面快照有容量上限：单条 100 万字符，总计 400 万字符、最多 160 条，避免同步读取大量 JSON 拖慢启动；超大条目不保留。
- 图片解码和聊天数据库打开仍有成本。这里消除的是已有页面数据仍被接口等待挡住的路径，没有声称每个像素都能零延迟出现。
- 编辑器原有的本地草稿异步恢复未重写；钱包页关闭期间的实时余额变化不另存新的页面快照。
- 成员搜索、验证资格和二维码等入口保留实时权限检查；广场帖子详情和圈子帖子页未新增持久化。内容流最多恢复 100 条，相册恢复已保存的首屏。
