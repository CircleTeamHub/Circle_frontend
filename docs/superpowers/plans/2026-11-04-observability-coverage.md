# App 可观测性覆盖补全

目标：补足生产 App 中“用户看见失败，但 Sentry 没有线索”的路径，复用现有上报、指标和脱敏入口。

- [x] 自动异常也携带本地诊断记录；保留诊断时间及当前/上一页面模板。
- [x] 已处理异常采用有时间窗口的限流；诊断记录失败不阻断异常上报。
- [x] HTTP 请求按路由模板、结果记录耗时；聊天发送/建连、对象存储上传补结果和耗时指标。
- [x] 补收藏、草稿和其他关键流程中确认遗漏的失败上报；保留正常取消/权限拒绝语义。
- [x] 针对隐私过滤、错误归因、限流恢复和成功/失败路径运行回归测试。
- [x] 更新监控使用说明与覆盖范围；说明新 App 包和 source map 的生效条件。

约束：不新增监控供应商或依赖，不上传业务内容、账号标识、媒体地址、请求体或原始任意报错文本。不把正常清理、用户取消视作故障。

验证：完整 Node 套件 3532 通过、30 跳过；完整 Jest 套件 168 个套件 / 1420 个用例通过；追加的可读数据契约错误回归及相关上报测试 21/21 通过。TypeScript、lint、diff 检查通过。Windows 构建脚本测试使用已安装的 Git Bash 在普通本机进程中运行，解决沙箱阻断 shell/目录链接的限制。没有触发真实用户故障或发送合成 Sentry 事件。

生效条件：这些 App 源码尚未重新打包发布。需要构建新包、上传同次构建的 source maps，再验证真实设备的事件和指标到达；服务器监控服务继续运行。
