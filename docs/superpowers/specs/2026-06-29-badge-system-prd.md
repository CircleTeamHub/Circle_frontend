# Circle Badge 系统 PRD

最后更新：2026-06-29

## 1. 背景

Circle 需要一套能服务社交关系、圈子贡献、内容创作和用户可信度的 Badge 系统。第一期目标不是一次性做大，而是建立稳定、可解释、可防刷、能上线的基础体系。

Badge 不应该只是装饰。它需要帮助用户快速判断一个人是谁、可信不可信、在圈子里有什么贡献，以及是否适合进一步互动。

## 2. 第一阶段范围

当前上线第一期先做 5 类 Badge，控制复杂度，保证上线质量。Moment Maker、Event Host、Trusted Friend 暂时作为后续候选，不进入本次实现范围。

| Badge | 类型 | 等级 | 核心指标 |
| --- | --- | --- | --- |
| VIP | 身份 | 1-5 | 会员等级 |
| New Joiner | 身份 | 无 | 注册时间 |
| Top Collaborator | 荣誉 | 1-3 | 收到合作认可数 |
| Verified Profile | 可信 | 无 | 资料完整 + 邮箱验证 + 公开至少一种联系方式 + 无违规 |
| Circle Builder | 贡献 | 无 | 圈主/管理员 + 圈子创建满 7 天 + 人数超过 100 + 无违规 |

## 3. 展示策略

### 3.1 个人主页主卡

- 展示用户手动选择的 3-5 个 Badge。
- 默认优先展示身份类、可信类、最高等级荣誉类 Badge。
- 用户可以调整展示顺序，但不应影响实际获得等级。

### 3.2 资料详情页

- 展示全部已获得 Badge。
- 按类别分组：身份、可信、荣誉、贡献、创作、组织、社交质量。
- 未获得的 Badge 可以不展示，避免制造压力。

### 3.3 聊天头像旁

- 只展示 1-2 个最强身份。
- 优先级建议：VIP > Verified Profile > Top Collaborator > 圈子相关 Badge。
- 这里不展示大量徽章，避免聊天界面变乱。

### 3.4 圈子成员列表

- 优先展示和圈子相关的 Badge。
- 例如 Circle Builder、Event Host、Top Collaborator。

### 3.5 获得瞬间

- 用轻提示，不使用强弹窗打断。
- 可以在个人页或通知里提供“刚获得 Badge”的记录。

## 4. 等级体系

### 4.1 普通 Badge

- 使用铜 / 银 / 金三级。
- 适合 Moment Maker、Event Host、Trusted Friend。

### 4.2 核心 Badge

- 使用 1-5 级。
- 第一阶段只适合 VIP。
- Circle Builder 第一阶段先不做等级，后续如果需要再升级为 1-5 级。

### 4.3 荣誉 Badge

- Top Collaborator 使用 1-3 级。
- 等级门槛保持为：100 / 1000 / 10000。

### 4.4 稀有 Badge

- 第一阶段暂不做。
- 后续可做无等级 Badge，例如限时活动、纪念、官方认证。

## 5. Badge 详细规则

### 5.1 VIP

用途：展示用户会员身份。

获得方式：

- 根据会员系统等级发放。
- VIP 1-5 与会员等级保持一致。
- 会员过期后隐藏或降级，具体跟随会员系统策略。

展示建议：

- 聊天头像旁优先展示。
- 个人主页主卡默认优先展示。

### 5.2 New Joiner

用途：降低新用户社交门槛，让其他用户知道这是新加入的人。

获得方式：

- 注册后自动获得。
- 建议展示周期：注册后 7-14 天。
- 如果用户存在严重违规、封禁、疑似垃圾账号，则不展示。

展示建议：

- 个人主页可展示。
- 聊天头像旁不优先展示。

### 5.3 Top Collaborator

用途：展示一个人在真实活动合作中获得过多少认可。

重要调整：

- 取消用户去别人 Profile 页面随意点赞的功能。
- Top Collaborator 不再由普通 Profile 点赞产生。
- 只由活动结束后的“合作认可”产生。

等级门槛：

| 等级 | 合作认可数 |
| --- | --- |
| 1 | 大于等于 100 |
| 2 | 大于等于 1000 |
| 3 | 大于等于 10000 |

Profile 展示：

- 展示累计合作认可数。
- 不展示最近获得认可的具体活动，避免侵犯隐私。
- 不需要理由标签。

### 5.4 Verified Profile

用途：展示用户资料可信度。它不是实名认证，也不应在文案里暗示官方已验证真实身份。

建议中文名：

- 可信资料

建议描述：

- 该用户已完善资料，并公开至少一种联系方式。

获得条件：

- 头像不是默认头像。
- 昵称已设置，并通过基础内容审核。
- 城市已设置。
- 个人简介达到最小长度，例如大于等于 10 个字符。
- 邮箱已验证。
- QQ号、手机号、微信号中至少填写一个。
- 已填写的 QQ号、手机号、微信号中，至少有一个开启“在个人主页展示”。
- 如果使用手机号计入 Badge 条件，手机号必须完成短信验证。
- 账号状态正常。
- 最近 30 天无严重违规、封禁、诈骗、骚扰等成立记录。

联系方式规则：

| 联系方式 | 作用 | 是否可计入 Verified Profile |
| --- | --- | --- |
| QQ号 | 补充站外联系渠道 | 填写并公开展示后可计入 |
| 微信号 | 补充站外联系渠道 | 填写并公开展示后可计入 |
| 手机号 | 更强联系与半身份验证 | 完成短信验证并公开展示后可计入 |

隐私说明：

- QQ号和微信号如果没有 OAuth 或平台侧验证，只能算“用户声明的联系方式”，不能表达为已验证归属。
- 手机号属于敏感信息，公开展示必须经过用户明确确认。
- 新填写的联系方式默认不公开。
- 用户必须主动打开“在个人主页展示”开关。

个人主页展示：

- 新增“联系方式”区域。
- 只展示用户主动公开的联系方式。
- 如果用户没有公开任何联系方式，不显示该区域。
- 手机号建议默认脱敏展示，例如 `138****1234`，并提供复制按钮。
- 微信号、QQ号可提供复制按钮。
- 点击复制时可给轻提示：请合理使用对方公开联系方式。

撤销条件：

- 用户移除头像、昵称、城市、简介中的关键资料。
- 邮箱失效或解绑。
- 所有联系方式被删除。
- 所有联系方式的公开展示开关关闭。
- 手机号失效或未验证。
- 出现严重违规、封禁、诈骗、骚扰成立记录。
- 联系方式被多人举报为虚假或骚扰引流，审核成立后撤销。

### 5.5 Circle Builder

用途：Circle Builder 是圈子建设贡献 Badge，用来展示用户正在建设或管理一个达到基础规模的健康圈子。

第一期先做简单规则，不做建设分、不做留存分、不做复杂活跃评分。

奖励对象：

- 圈主。
- 管理员。

获得条件：

- 用户是该圈子的圈主或管理员。
- 圈子创建满 7 天。
- 圈子未被封禁。
- 圈子未被标记违规。
- 圈子人数超过 100。

撤销或隐藏条件：

- 用户不再是圈主或管理员。
- 圈子被封禁。
- 圈子被标记违规。
- 圈子人数降到 100 或以下。

展示建议：

- 在个人主页展示为 `Circle Builder`。
- 在圈子成员列表中优先展示给圈主和管理员。
- 第一阶段不显示等级和分数。

### 5.6 Moment Maker

用途：奖励持续发布高质量动态的人。

获得方式建议：

- 发布有效动态。
- 动态获得真实互动，例如评论、收藏、报名转化。
- 内容未被删除、未违规。
- 低质量刷屏动态不计入。

等级建议：

- 铜：稳定发布有效动态。
- 银：动态有持续互动。
- 金：动态长期高质量，并带来正向社交互动。

### 5.7 Event Host

用途：奖励组织活动或报名帖的人。

获得方式建议：

- 发布有效活动/报名帖。
- 活动有真实报名者。
- 活动结束流程完成。
- 活动没有被多人举报为虚假。
- 报名者反馈较好。

等级建议：

- 铜：成功组织一定数量活动。
- 银：活动完成率、报名质量较好。
- 金：长期稳定组织高质量活动。

### 5.8 Trusted Friend

用途：奖励低负反馈、高质量社交关系的人。

获得方式建议：

- 好友关系稳定。
- 私信、互动、活动合作没有高比例负反馈。
- 被拉黑、举报、骚扰成立记录较低。
- 不仅看好友数量，也看关系质量。

重要限制：

- 社交质量 Badge 必须结合负反馈。
- 举报、拉黑、骚扰、诈骗成立较多的人不能获得或展示。

## 6. Top Collaborator 活动认可设计

### 6.1 核心流程

1. 用户发布圈子活动/报名帖。
2. 其他用户报名。
3. 活动默认 24 小时后自动结束。
4. 活动结束后，从圈子帖子列表移除。
5. 发帖者收到通知：活动已自动结束，请进入结束流程。
6. 发帖者在报名者列表中选择最多 3 人，给予合作认可。
7. 被认可用户的合作认可数增加。
8. 合作认可数达到门槛后，升级 Top Collaborator。

### 6.2 活动结束规则

- 圈子活动第一期不提供自定义结束时间。
- 活动发布后 24 小时自动结束。
- 活动结束后从圈子帖子列表移除。
- 发帖者收到通知，并进入活动结束流程。
- 后续版本可考虑让发帖者手动提前结束，但第一期先保持简单。

### 6.3 结束流程页面

页面需要支持：

- 展示活动标题、报名人数、结束状态。
- 展示所有报名者。
- 提供搜索栏，因为报名人数可能上百。
- 支持选择最多 3 个报名者。
- 已选择人数需要明确提示，例如 `2/3`。
- 提交前二次确认。
- 提交后不可随意修改，除非后续设计申诉/纠错机制。

不需要：

- 不需要填写理由标签。
- 不需要在 Profile 公开展示最近获得认可的具体活动。

### 6.4 反作弊规则

只靠“每个帖子最多 3 个”不够，需要多层限制。

活动有效性：

- 活动至少有 3 个报名者。
- 活动开启时间至少超过 30 分钟或 1 小时。
- 活动帖子未被删除。
- 活动帖子未违规。
- 报名者不能是发帖者本人。
- 同一个活动最多产生 3 个合作认可。

发帖者可信度：

- 发帖者账号注册满 7 天。
- 发帖者最近 30 天无严重违规。
- 发帖者不能短时间创建大量活动刷认可。
- 同一个发帖者给同一个人，在 30 天内最多计入 2 次。

关系去重：

- 同一个圈子给同一个人的合作认可，30 天内最多计入 5 次。
- 同一批账号互相反复刷活动，需要触发风控。
- 如果活动参与者高度重复，后续认可降权或不计入。

负反馈否决：

- 被认可用户最近 30 天有骚扰、诈骗、严重举报成立，暂停展示。
- 活动被多人举报为虚假活动，该活动产生的认可撤销。
- 账号被封禁时，Badge 隐藏。

### 6.5 实现难度判断

第一期容易实现：

- 活动 24 小时自动结束。
- 活动结束通知。
- 结束流程选择最多 3 人。
- 活动至少 3 个报名者。
- 发帖者注册满 7 天。
- 同一活动最多 3 个合作认可。
- 报名者不能是发帖者本人。
- 基础违规/封禁否决。

第一期可以实现但需要后端认真设计：

- 同一个发帖者给同一个人 30 天最多计入 2 次。
- 同一个圈子给同一个人 30 天最多计入 5 次。
- 删除/违规活动撤销认可。
- Top Collaborator 数量重新计算或增量同步。

后续版本再做：

- 同一批账号互刷识别。
- 高重复参与者降权。
- 风控模型。
- 活动质量评分。

## 7. 后端需求

### 7.1 Badge 数据

需要支持：

- Badge 定义表。
- 用户已获得 Badge 表。
- Badge 等级和进度。
- Badge 是否展示。
- 用户手动选择的展示顺序。

### 7.2 Top Collaborator

需要支持：

- 活动状态：active / ended / completed / deleted / violation。
- 报名记录。
- 合作认可记录。
- 认可来源活动 ID。
- 认可发起人 ID。
- 被认可用户 ID。
- 认可是否计入 Badge。
- 撤销状态和撤销原因。

需要避免：

- 同一个活动重复提交认可。
- 超过 3 人。
- 发帖者认可自己。
- 不满足活动有效性时计入认可。

### 7.3 Verified Profile

Profile 接口需要支持：

- 返回当前访问者可见的公开联系方式。
- 不应该无条件返回手机号、微信号、QQ号。
- Verified Profile 的获得状态建议后端动态计算，或在资料变更、邮箱验证、联系方式变更、违规状态变化时重新计算。

Settings 接口需要支持：

- 编辑 QQ号、微信号、手机号。
- 独立设置每个联系方式是否在个人主页展示。
- 新联系方式默认不公开。
- 手机号验证状态。
- 手机号公开展示二次确认。

### 7.4 定时任务

需要支持：

- 扫描超过 24 小时的活动，自动结束。
- 发送活动结束通知。
- 对未完成结束流程的活动进行提醒。
- 周期性重新计算 Badge。
- 撤销违规活动产生的认可。

## 8. 前端需求

### 8.1 个人主页

- 主卡展示用户选择的 3-5 个 Badge。
- 展示 Top Collaborator 合作认可数。
- 展示 Verified Profile 状态。
- 新增联系方式区域，只显示用户公开的 QQ号、微信号、手机号。
- 手机号默认脱敏展示。
- 没有公开联系方式时不显示联系方式区域。

### 8.2 Badge 详情页

- 按类别展示所有已获得 Badge。
- 展示等级、进度、获得时间。
- Top Collaborator 不展示具体活动来源。

### 8.3 活动结束流程

- 展示报名者列表。
- 提供搜索栏。
- 支持最多选择 3 人。
- 提供提交确认。
- 提交后显示成功状态。
- 网络失败时可重试。
- 重复点击提交需要防抖或 loading 锁定。

### 8.4 设置页联系方式

- QQ号、手机号、微信号各自独立编辑。
- 每个字段有独立“在个人主页展示”开关。
- 新填写的联系方式默认不公开。
- 打开公开展示时给出隐私提示。
- 手机号公开展示需要二次确认。
- 手机号显示已验证/未验证状态。

## 9. 安全与隐私

- 不在日志里打印手机号、微信号、QQ号。
- 不在错误上报里上传完整联系方式。
- 后端接口必须按访问权限过滤联系方式。
- 不提供通过手机号、微信号、QQ号反向搜索用户的能力，除非后续专门设计。
- 联系方式修改需要频率限制，例如每天最多 3 次。
- Profile 举报入口需要覆盖联系方式虚假、骚扰、引流、诈骗。
- Badge 不应该让违规账号获得额外可信背书。

## 10. 测试建议

### 10.1 Top Collaborator

需要测试：

- 活动少于 3 个报名者时不能产生认可。
- 发帖者不能认可自己。
- 同一活动最多认可 3 人。
- 重复提交不会重复计数。
- 活动删除后认可撤销。
- 活动违规后认可撤销。
- 100、1000、10000 门槛正确升级。
- 100 正好可以获得 1 级。

### 10.2 活动结束流程

需要测试：

- 24 小时自动结束。
- 自动结束后从圈子帖子列表移除。
- 发帖者收到通知。
- 报名者上百时搜索可用。
- 慢网络提交不会重复创建认可。
- 提交失败可以重试。

### 10.3 Verified Profile

需要测试：

- 没有公开联系方式时不能获得 Badge。
- 只填写 QQ 并公开展示可以获得 Badge。
- 只填写微信并公开展示可以获得 Badge。
- 手机号未验证不能作为 Badge 条件。
- 手机号验证并公开后可以作为 Badge 条件。
- 关闭所有公开展示开关后撤销 Badge。
- 个人主页不泄露未公开联系方式。
- 手机号脱敏展示。

### 10.4 隐私回归

需要测试：

- 未登录用户看到的联系方式范围。
- 登录用户看到的联系方式范围。
- 自己查看自己 Profile 时的展示逻辑。
- 被封禁用户 Badge 隐藏。
- 严重违规用户 Badge 撤销。

### 10.5 Circle Builder

需要测试：

- 圈主在圈子创建满 7 天、人数超过 100、未违规时获得 Badge。
- 管理员在圈子创建满 7 天、人数超过 100、未违规时获得 Badge。
- 圈子创建未满 7 天时不能获得 Badge。
- 圈子人数等于 100 时不能获得 Badge，必须超过 100。
- 圈子被封禁或标记违规后 Badge 隐藏或撤销。

## 11. 第一阶段上线建议

必须第一期完成：

- VIP
- New Joiner
- Top Collaborator 基础活动认可
- Verified Profile 基础规则
- Circle Builder 基础规则
- Badge 展示组件
- Profile 展示
- 报名管理页提交合作认可入口
- 关键反作弊限制
- 24 小时自动结束活动。
- 活动结束通知。
- 自动结束后从圈子帖子列表移除。

可以后续完善：

- Moment Maker。
- Event Host。
- Trusted Friend。
- 复杂风控模型。
- Badge 纪念款。
- 活动质量评分。
- 互刷账号图谱识别。
- Badge 获得历史页。
- Badge 分享图。

## 12. 当前讨论结论

- 第一阶段当前上线先做 5 个 Badge：VIP、New Joiner、Top Collaborator、Verified Profile、Circle Builder。
- Partner 和 Top Collaborator 是同一个概念，保留 Top Collaborator。
- Top Collaborator 等级保持 100 / 1000 / 10000。
