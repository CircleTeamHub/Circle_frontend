# PR #159 自毁消息审查修复设计

## 目标

修复 PR #159 审查中确认的本地隐私残留、策略竞态和过期状态不一致问题，同时保持离线可用与现有聊天交互。

## 方案比较

1. 仅在连接 socket 后刷新策略：实现最小，但离线或连接失败时仍会用错误策略水合缓存，排除。
2. 先以本地策略水合，再异步纠正：首屏快，但会短暂展示应销毁内容，排除。
3. 服务器策略成功后再水合，失败时回退账户隔离的本地策略：正确性优先，且保留离线能力，采用。

## 设计

- Socket manager 为每次策略 GET 分配单调请求序号，并在会话切换、较新的 GET 或设置页写入后拒绝旧响应。首次连接仅在策略解析完成（或请求失败）后水合本地数据库。
- Store 的策略写入区分本地权威写入与远程刷新写入；本地写入递增修订号。过期清理立即更新内存，会在同一个队列事务内批量删除 messages、FTS 关联项和过期 outbox，再持久化清理后的预览。
- 水合等待该持久化清理后才读取 outbox，防止已过期的失败发送重新进入时间线。清理会把受影响会话的未读数归零，直到下一次服务器快照给出权威值。
- 启动最近到期计时器，App 前台恢复和策略/会话快照变化时重新计算。计时器只触发清理，不发送网络写入。
- PrivacySettingsScreen 为每个请求捕获当前聊天账号和请求序号；响应只可写入仍匹配的账号。
- 自毁策略适用的图片使用 `expo-image` 的 `memory` 缓存；首次遇到此类会话时清一次 `expo-image` 磁盘缓存，移除策略启用前遗留的图片字节。该一次性性能代价优先于私聊图片的保留风险。

## 验收

- 冷启动在在线时先应用服务端策略，在离线时才采用本地策略。
- 旧策略 GET、跨账号设置响应和过期 outbox 均不能恢复或覆盖较新的安全状态。
- 到期后本地时间线、预览、未读数、SQLite messages/FTS/outbox 均不再暴露正文。
- 多会话清理以单个排队事务完成；自毁图片不写入磁盘缓存。
